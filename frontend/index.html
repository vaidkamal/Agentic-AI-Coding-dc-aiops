Specification-driven build record

the spec this console was built from

1 · Specification

Problem. Hall 2 operators react to alarms one metric at a time; thermal and power events are spotted late and root cause takes hours.

Goal. A web console that detects anomalies across racks, correlates them to a probable cause, and proposes a remediation the operator can approve in one tap.

User stories

  • As a NOC engineer I see hall health at a glance so I know where to look first.
  • As a NOC engineer I get an incident with a probable root cause and confidence, not just a threshold alarm.
  • As a shift lead I approve an automated runbook and watch it execute step by step.
  • As a capacity planner I see when power will reach 80 % of design so I can order ahead.

Acceptance criteria

  • AC-1 Anomaly flagged within 3 samples when a metric exceeds 3 σ of its rolling baseline.
  • AC-2 ≥ 3 thermal anomalies in one zone are merged into a single CRAC incident.
  • AC-3 Runbooks require explicit approval; no auto-execution.
  • AC-4 Incident auto-resolves after 5 consecutive normal samples.
  • AC-5 Works on a phone (≥ 360 px) and respects system light/dark theme.

2 · Planning

a

Decompose: telemetry simulator → rolling-stats anomaly detector → zone correlator → incident manager → runbook executor → UI.

b

Tools: single self-contained HTML, Chart.js for time series, no backend (telemetry is simulated in-page; swap tick() for a WebSocket feed from Prometheus/SNMP/DCIM).

c

Execution: build the data layer first, then detection, then UI; verify each AC with an injected fault.

3 · Coding & iteration

Three injectable faults exercise every path: CRAC failure (correlation), runaway process (single-rack CPU), PSU loss (offline detection). Use the “Inject fault” control in the header.

4 · Review & validate

  • Security: no external calls, no stored credentials, runbooks are approval-gated.
  • Performance: 24 racks × 3 metrics at 0.5 Hz; charts update in place.
  • Compliance: all actions are logged in the incident timeline.

5 · Deployment

Published as a hosted page. Next: connect real telemetry, add SSO, persist incidents to a ticketing system (ServiceNow/Jira), and route approvals to on-call.
